Know when an MCP server changes underneath your agent.

Every night since 30 August 2026 a crawler has visited every server in the official MCP registry and recorded the exact tool surface it served: names, descriptions, input schemas. The observations go into an append-only Merkle log with a signed tree head published daily. Nothing on this site asks to be trusted; every number can be recomputed.

Lock, like package-lock.json

mcp.lock pins the tool surface of each MCP server your project uses. A GitHub Action re-probes them, fails the build when one differs, and opens an issue with the diff: tools added, removed, or edited in place.

mcpobs lock context7=https://mcp.context7.com/mcp
git add mcp.lock

# .github/workflows/mcp-lock.yml
- uses: yassinht/mcp-transparency-log@v1

Each entry also carries the jcs-v1 tool-set digest (RFC 8785) that other registry observers share, so a lock written here can be compared with their records. Setup in four steps. This repository runs it on itself.

Scan, without a model

Thirteen rules a human can re-run look for text aimed at the model rather than the user: "ignore previous instructions", "forward the conversation", hidden bidi characters. Every match is quoted; none is called malicious.

What this is, and is not

It is

A record of what publicly listed, unauthenticated MCP servers served on each night, kept in a form that lets a stranger prove it was not rewritten. The signing key proves one operator stood behind each head; the published leaf hashes let anyone rebuild the tree and compare.

It is not

Not a judgement of any server. Not coverage of servers that require credentials, of local stdio servers, or of anything outside the official registry. Not yet witnessed by a second independent crawler: a log with one operator can prove consistency, not truth.

It is not alone

Other people read the same servers: HISTOR, MCP Drift Observatory, mcpcost, CrawlCheck. Observers that disagree expose a lying server or a bug in one of them, so every night this log publishes its observations as a cross-check list in the digest format they share. Every past night's copy stays at a link pinned to the commit that published it, with its SHA-256. Who started when.
