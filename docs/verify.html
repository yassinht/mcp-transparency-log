Verify the log yourself

A transparency log that only its operator can check is a database with a nice name. This one is checked from a clean clone, with nothing but what is in the repository.

What is published

Signed tree heads

One file per night in heads/: the tree size, the root hash, a timestamp, and an Ed25519 signature over them. The public key is heads/key.pub. Each head commits to every observation before it.

Leaf hashes

Thirty-two bytes per observation in docs/data/leaves/, one file per night, in log order. Around 800 KB a day. These are what the tree is built from, so with them you can rebuild it without the multi-gigabyte archive.

The tree algorithm

RFC 6962, through the same sumdb/tlog package that implements the Go checksum database. Nothing bespoke is between you and the hashes.

Run it

git clone https://github.com/yassinht/mcp-transparency-log
cd mcp-transparency-log
go run ./cmd/mcpobs verify --leaves docs/data/leaves --heads heads --pubkey heads/key.pub

For every published head, the command rebuilds the tree from the leaf hashes up to that head's size, recomputes the root, checks the signature with the public key, and prints VERIFIED or says exactly which head disagrees. It takes a minute on a laptop.

Witnesses

The tree stops a rewrite of history. It does not stop an operator from showing different readers different histories. So each head is also published as a standard checkpoint in heads/checkpoint, signed with the same key, and sent each night to the witnesses listed in heads/witnesses. A witness run by someone else cosigns only a tree that extends the last one it saw.

go run ./cmd/mcpobs verify-checkpoint

What that proves, and what it does not

It proves

That the heads were signed by the holder of the key, that each one is consistent with the published leaves, and that no observation was altered or removed after a head committing to it was published. Hold yesterday's head and you can detect any rewrite of yesterday's history.

It does not prove

That the leaves describe reality. A single operator could log an observation that never happened and sign it consistently, and a witness would cosign it, because a witness checks consistency, not truth. Catching that needs a second party running its own crawler against the same servers and comparing. The nightly peer list exists for that comparison.

From a hash to a server

A leaf is the SHA-256 of one observation record: server, endpoint, outcome, the canonical surface hash, the tool names, and the content hashes of the raw bytes that were archived. The raw archive is gigabytes and lives on the crawler; it is not served publicly yet. The surface hash, however, is checkable against the server itself right now:

mcpobs lock https://tandem.ac/mcp      # probes the live server, prints its surface_sha256

If that hash equals the one on the server's history page, the server is serving tonight exactly what the log recorded. If it differs, the log will record the difference tonight, and so will anyone who runs the same command.
