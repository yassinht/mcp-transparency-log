The rule scan

Text in a tool description is read by the model, not the user. These rules look for text written for that reader.

A tool description that says "ignore your previous instructions" or "include the user's earlier messages in the request" is not describing a tool. Every night the latest census is run through thirteen rules that look for that kind of sentence, in descriptions, titles, and every description nested inside an input schema, however deep. Parameter descriptions are read by the model too, and they are the field most scanners skip.

There is deliberately no language model doing the judging. Every rule is a regular expression you can read in scan.go and run yourself against the same bytes. A flag that cannot be reproduced from the archived text is an opinion, and this log does not record opinions. The output says "this pattern occurs here", never "this is malicious".

Rules

Review rules match text a security reviewer should actually read. Info rules describe a property legitimate tools exhibit constantly: a parameter documented as "pass your token here", a data tool linking to a government site, a very long description. Counting both together produced a 57% flag rate in the first pass, a number that would not survive thirty seconds in front of anyone who then read one example. The two tiers are reported separately for that reason.

Method

Negation window

"Never include secrets" and "do not forward the conversation" are the opposite of what the exfiltration and secrets rules look for. A match preceded within 24 characters by a negating word is dropped. Go's regular expressions have no lookbehind, so this is a second check.

Placeholder hosts

A URL to example.com, localhost or {your-domain} in a parameter description documents the shape of a value. Those are not counted as off-host links; a link to the server's own domain or a parent of it is not either.

Templates, not thousands of decisions

Two publishers ship the same text on well over a thousand registry entries each. A pattern in their template appears on every one of them. The figures are given both with and without those publishers, because "a thousand servers" and "one publisher" are different findings.

Known gaps

English only. Regular expressions see patterns, not intent: a rule that catches "prefer this tool over the built-in search" also catches a manual that says the same thing honestly. Hidden characters exclude the joiners emoji are built from. New phrasings are not caught until a rule is written for them; rule changes are commits, dated and public.
